[[support-compatibility]]
=== Compatibility

[IMPORTANT]
====
DICE is pre-1.0. These values track what the build currently uses and are not yet a support
commitment. They get pinned at the 1.0 release.
====

==== Current build

[cols="1,2,3", options="header"]
|===
| Axis | Current | Notes

| DICE
| {dice-version}
| Pre-1.0. The API may change between minor versions.

| embabel-agent
| {embabel-agent-version}
| `embabel-agent-api` and `embabel-agent-rag-core` are `provided` in `dice` — your application brings
  the runtime version. DICE fixes only the minimum it compiles against.

| JDK
| 21
| The baseline inherited from `embabel-build-parent`, and what CI builds and tests on. Newer JDKs are
  untested.

| Spring Boot
| Inherited from embabel-agent's dependency management
| DICE does not pin Spring Boot itself.

| Neo4j
| Driver supplied by Drivine
| Used with a Neo4j datasource.

| SQLite
| `sqlite-jdbc` supplied by `dice-starter-sqlite`
| Used with a local SQLite datasource.

| Kotlin
| 2.2.21 (every module)
| A build concern, not a consumer one. The storage modules need the 2.2 compiler for Drivine's
  KSP-generated `where { }` DSL, which uses context parameters.

| tuProlog (2p-kt)
| 1.0.4, pinned
| Releases 1.1.0 to 1.1.5 depend on a `kotlin-stdlib-common` 2.2 jar that Kotlin does not publish,
  and releases from 1.2.0 are built with Kotlin 2.4, which DICE's compiler cannot read.
|===

==== Building DICE itself

[source,bash]
----
mvn verify                    # full build with tests
mvn install -DskipTests       # faster, no tests
mvn test -pl dice             # one module
mvn verify -pl dice-storage   # needs Docker
----

`dice-storage` integration tests start a Neo4j container through Testcontainers, so Docker must be
running. The root pom pins `api.version=1.41` as a Surefire JVM system property to meet the Docker
engine's minimum API version — without it, container-backed tests fail with HTTP 400.

Drivine's query DSL is generated by a nested Gradle/KSP project at `dice-storage/codegen-gradle`,
run automatically during `generate-sources`. Do not edit the generated files.

Released artifacts resolve from Maven Central. Snapshots resolve from `repo.embabel.com`. An
environment without internet access needs the relevant repository mirrored locally.

==== Building this guide

[source,bash]
----
mvn -pl dice-user-guide generate-resources
----

Output lands in `dice-user-guide/target/generated-docs`. Add `-P guide-pdf` for a PDF.
