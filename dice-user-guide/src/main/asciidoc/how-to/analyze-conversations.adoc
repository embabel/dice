[[how-to-analyze-conversations]]
=== Analyse a conversation incrementally

*Prerequisites*: `dice`, a configured LLM, a `PropositionRepository` and a `ChunkHistoryStore`.

A conversation is not a document. It arrives a turn at a time, the same claim gets restated and
revised, and the user themselves is an entity the extractor should already know about.

==== The incremental analyser

`IncrementalAnalyzer` processes an `IncrementalSource` and remembers what it has already seen.
`ConversationSource` wraps a conversation; `ConversationSegmenter` decides where one unit of analysis
ends and the next begins, so a claim spanning three turns is not cut in half.

[source,java]
----
var source = new ConversationSource(conversation);
var window = analyzer.analyzeWindow(source, context);
if (window != null) {
    window.getResult().persist(propositionRepository, entityRepository);
    window.markProcessed();
}
----

Re-analysing the same conversation is cheap: `ChunkHistoryStore` reports what has already been
processed and the analyser skips it. A window is recorded when `markProcessed()` is called, so a
failed `persist` leaves it for the next call. `analyzeWindow` is on `AbstractIncrementalAnalyzer`,
so declare the analyser as that class or a subclass such as `PropositionIncrementalAnalyzer`.

==== Tell the context who is talking

Without this, "I prefer the early recordings" produces a claim about nobody.

[source,java]
----
var context = SourceAnalysisContext
        .withContextId(user.currentContext())
        .withEntityResolver(entityResolverForUser(user))
        .withSchema(dataDictionary)
        .withRelations(relations)
        .withKnownEntities(KnownEntity.asCurrentUser(user));
----

`KnownEntity.asCurrentUser(...)` is the important line: it gives the resolver a first-class identity
for the speaker, so first-person claims attach to them.

==== Drive it from events

Conversation analysis costs an LLM call, so it should not sit in the request path.
`ConversationAnalysisRequestEvent` exists for exactly this. The listener has no transaction of its
own. It stores the result through a `@Transactional` method on another bean and marks the window
when that method has returned, which is after the commit.

[source,java]
----
@Async
@EventListener
public void onConversationExchange(ConversationAnalysisRequestEvent event) {
    var context = SourceAnalysisContext
            .withContextId(event.user.currentContext())
            .withEntityResolver(entityResolverForUser(event.user))
            .withSchema(dataDictionary)
            .withRelations(relations)
            .withKnownEntities(KnownEntity.asCurrentUser(event.user));

    var source = new ConversationSource(event.conversation);
    var window = analyzer.analyzeWindow(source, context);
    if (window != null) {
        claimStore.store(window.getResult());
        window.markProcessed();
    }
}
----

[source,java]
----
@Service
public class ClaimStore {

    @Transactional
    public void store(ChunkPropositionResult result) {
        result.persist(propositionRepository, entityRepository);
    }
}
----

A store that fails or rolls back throws, and the window is left for the next event. Marking inside
the transaction is correct only when the `ChunkHistoryStore` takes part in that transaction.

`SourceAnalysisRequestEvent` is the general form for non-conversation sources.

==== Turn on revision

In a conversation the same thing gets said repeatedly, and sometimes retracted. Without revision you
accumulate near-duplicates; with it, restatements reinforce and reversals are classified as
contradictions.

[source,java]
----
var pipeline = PropositionPipeline
        .withExtractor(extractor)
        .withRevision(reviser, propositionRepository);
----

Revision compares against what is already stored and classifies each new claim as new, merged,
reinforced or contradicted. It still persists nothing — `hasRevision` tells you which set
`propositionsToPersist()` will return.

==== Scope per user

Give each user their own `ContextId`. It is the boundary that keeps one user's beliefs out of
another's retrieval, and it is what makes "forget everything about me" a bounded operation.
